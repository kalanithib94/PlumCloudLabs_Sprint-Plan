1. Before you start

1.1 How to open the planner

Open the live app in Chrome or Edge (needed for CSV import, clipboard copy, and speech-to-text):

https://plum-cloud-labs-sprint-plan.vercel.app/

The planner must be served over HTTP — do not open HTML files directly as file:// URLs.

Local development only: from the project folder run python -m http.server 8080, then open http://localhost:8080/planner/index.html.

1.2 What data is stored where

DataLocationNotes
Current draft + named savesBrowser localStorage key sprintPlanner.v3Per browser, per device. Not synced to a server.
Downloaded release HTMLYour diskSelf-contained file; can be re-imported via Import HTML.
Jira CSVNever storedRead once at import; only assignment rows are kept in the plan.

1.3 Constants (fixed by the app)

  • Hours per working day: 8 (not editable in the UI).
  • Working days: Weekdays (Mon–Fri) between sprint start and end dates, unless you override the count in the Sprint Header pill.
  • Default working days when dates are blank: 10 (used only for capacity math until you set real dates).

3.2 What you can change

  • Switch tab: Click any tab. The current tab’s draft is auto-saved to localStorage before switching.
  • Team roster: Fully editable per tab (add/remove/rename members in the Team table). Defaults above apply only on a fresh / cleared plan.

3.3 What you cannot change in the UI

  • Tab labels (Dev, Marketing, EE, Hynoyo) and which teams exist — fixed in app configuration.
  • Enabling Phases on non-EE tabs — if a saved plan used Phases on another team, the app forces Per-Person on load.

6.1 Saved sprints bar

Appears below the action bar when two or more named saves exist for the active tab. Click a chip to load; ✕ deletes that save. Active save is highlighted.

6.2 Auto-save draft

Every input/change debounces (~500 ms) to localStorage as the tab’s current draft. Survives refresh without clicking Save. Named saves are still created only via Save.

7.3 Copy Cursor prompt

  1. Click Copy Cursor prompt on the Brain dump card.
  2. Paste into Cursor chat and send.
  3. Cursor returns JSON only (no markdown).
  4. Click Paste JSON from Cursor in the sticky bar and apply.

7.4 ROVO prompt (Jira export)

In the collapsible “How it works” section, copy the ROVO prompt. Example:

List all child items of the epic "EE Sprint 04" as a table with these columns: Key, Summary, Type, Status, Priority, Assignee, Reporter, Due Date, Created, Updated, Assignee-V2, Co-Assignee-V2, Story Point Estimate

Export ROVO’s table as CSV, then Import CSV. Map Assignee-V2, not the manager-echo Assignee column.

8.1 Colour rules

ColourCondition
GreenPlanned ≤ 80% of available
AmberPlanned > 80% and ≤ 100% of available

In Phases mode, planned hours = sum of phase row hours for that person. In Per-Person mode, planned = sum of all JIRA rows (including locked shared rows).

11. Per-Person structure — Shared JIRAs

Shared JIRAs represent work split across multiple people. The planner creates locked rows on each person’s card (labelled “shared”).

11.1 + Add shared JIRA — defaults

FieldDefaultEditable
JIRA titleBlankYes
Total hours0Yes
Start / End dateBlankYes — syncs to all derived person rows
Member chipsNone checkedCheck to include; enter hours per person

11.2 Controls

  • Auto-split: Divides total hours equally across checked members (rounded).
  • Allocation pill: Shows allocated h / total h. Green = match; amber = under; rose = over allocated.
  • ✕: Deletes shared JIRA and removes derived rows from all person cards.
Do not duplicate a shared JIRA in a person’s personal assignment list — use shared splits only. Cursor JSON should move items to sharedJiras and remove them from personal lists.

12.3 CSV import row defaults (after Apply)

  • JIRA text = {Issue key} — {Summary} (either part alone if the other missing).
  • Hours = parsed from estimate column (see Section 13).
  • Start = CSV start column if mapped, else sprint start date if set, else blank.
  • End = CSV due column if mapped, else sprint end date if set, else blank.

13. Import Jira CSV — mapping modal

Opened after you pick a .csv file via Import CSV. Parsing uses PapaParse (header row = column names).

13.1 Step-by-step

1 Click Import CSV in the sticky bar.

2 Choose your Jira/ROVO export file.

3 Review file line: filename · row count · column count.

4 Adjust column mapping dropdowns (auto-detected — verify especially Assignee).

5 Set estimate unit and import mode.

6 Fix any unmatched assignees in the remap section.

7 Scan the preview table (green match / red no match).

8 Click Apply import (enabled only when ≥ 1 matched row).

13.2 Column mapping fields

ControlRequiredAuto-detection hintsYour action
Issue key columnOptional“issue key”, “key”, “issue id”Select column with JIRA keys (e.g. V2-8748). Choose “(none)” if keys live elsewhere.
Summary columnOptional“summary”, “title”Ticket title combined with key for JIRA cell text.

13.3 Estimate unit options

UnitHow values are interpreted
Auto-detectJira duration strings (1d 4h, 30m); pure numbers ≥ 1000 treated as seconds; smaller numbers as hours.
HoursPlain numbers and d/h/m/s suffix strings as hours/minutes/seconds.
SecondsNumeric values divided by 3600 (Jira “Original Estimate” in seconds).
Story pointsNumeric × “Hours per story point”. Blank/em-dash → 0 hours.

Blank tokens treated as empty: em-dash —, en-dash, hyphen-only cells.

13.4 Assignee matching

Automatic fuzzy match order:

  1. Exact full name (case-insensitive)
  2. First name match (≥ 3 characters)
  3. Partial contains match

13.7 Modal footer buttons

  • Pick a different file — re-open file picker without closing modal.
  • Cancel / ✕ / backdrop / Escape — discard import context.
  • Apply import — writes matched rows to person cards; switches to Per-Person view; toast with count.
Replace mode detail: Removes all personal (non-shared) JIRA rows from every person before importing. Shared-derived rows are kept so shared JIRA sync is not broken.

14. Paste JSON from Cursor modal

14.1 Opening and applying

  1. Click Paste JSON from Cursor.
  2. Paste JSON into the large textarea (with or without surrounding whitespace).
  3. Click Apply JSON.

14.2 What JSON replaces

Replaces sprint header fields, team, style, phases, shared JIRAs, and assignments for the current company tab.

14.3 Brain dump behaviour

Your current brain dump is preserved unless the JSON includes a non-empty brainDump field.

14.4 Validation errors

Invalid JSON or schema errors show in red below the textarea. Modal stays open for correction.

14.5 Cancel

Cancel, ✕, backdrop, or Escape closes without changes.

15. Import HTML and Download HTML

15.1 Download HTML

  • Builds a standalone release plan matching the pastel layout.
  • Embeds full planner JSON in a script tag for round-trip editing.
  • Filename: sprint-NN-release-plan.html (NN from sprint number, or xx if blank).

15.2 Import HTML

  1. Click Import HTML.
  2. Select a file previously downloaded from this planner.
  3. Preferred: reads embedded JSON (full round-trip).
  4. Fallback: scrapes visible layout from older HTML files (partial — re-download after edits for full round-trip).

15.3 Preview

Same generated HTML as Download, opened in a new browser tab. Allow pop-ups if blocked.

17. Formulas, defaults, and colour coding

17.1 Core formulas

workingDays (auto) = weekdays between sprint start and end (Mon–Fri only)
sprintWorkingDays  = override if set and > 0, else auto (else 10 if no dates)

availableHours(member) = (sprintWorkingDays − leaveDays) × 8 × allocationPct ÷ 100

planned (per person, Per-Person) = Σ assignment.hours (includes shared rows)
planned (per person, Phases)     = Σ phaseRowHours for each phase row

buffer (metric strip) = max(0, totalCapacity − totalPlanned)

18. End-to-end workflow checklist

18.1 Standard sprint (Jira → release plan)

  1. Select your company tab.
  2. Enter sprint name, number, start and end dates; adjust team leave/alloc %.
  3. In Jira ROVO, run the export prompt; save as CSV.
  4. Import CSV → map Assignee-V2 and estimate columns → remap unmatched names → Apply.
  5. Type brain-dump rearrangements (shared splits, removals, hour changes).
  6. Copy Cursor prompt → Cursor chat → Paste JSON from Cursor.
  7. Review feasibility bars; adjust manually or via another Cursor pass if needed.
  8. Save a named copy in the browser.
  9. Preview then Download HTML for stakeholders.

18.2 Phases-based release sprint (EE only)

  1. Select EE tab → Sprint structure → Phases.
  2. Set sprint dates and team leave/alloc %.
  3. Fill each phase start/end; adjust who participates and alloc % per phase.
  4. Run feasibility check; use Preview/Download when ready.

18.3 Edit an existing release plan

  1. Import HTML from a previous download.
  2. Edit in planner; Save optional.
  3. Download HTML again (embeds fresh JSON for next round-trip).
